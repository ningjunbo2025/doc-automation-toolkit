# 远程项目交付清单

> 项目：数据整理与文档自动化
> 周期：7 天（含 1 轮验收修改）
> 更新：2026-10-19

## 一、需求确认

开工前把下面几件事对齐，避免做到一半才发现方向不对：

1. **输入**：原始数据格式、字段含义、数据量级。
2. **输出**：文件类型、命名规则、排版模板。
3. **边界**：哪些情况需要人工判断，哪些可以自动处理。
4. **验收**：抽样比例、核对方式、修改轮次。

## 二、交付节点

| 节点 | 内容 | 交付物 | 状态 |
|---|---|---|---|
| D1 | 需求与样例确认 | 需求说明、样例文件 | 已完成 |
| D2 | 核心流程跑通 | 脚本、测试数据 | 已完成 |
| D3 | 全量处理与自查 | 成品文件、校验报告 | 进行中 |
| D4 | 验收与修改 | 最终交付包、使用说明 | 待开始 |

## 三、技术方案（示例）

```python
from pathlib import Path

def collect(md_dir: str) -> list[Path]:
    """收集待处理的 Markdown 文件。"""
    return sorted(Path(md_dir).rglob("*.md"))

for path in collect("demo"):
    print("processing:", path)
```

## 四、验收标准

- 所有输出文件命名一致，数量与输入清单一致。
- 随机抽取 **10%** 记录，与源数据逐字段核对。
- 表格、标题、代码块在 Word 中显示正常，无溢出与缺字。
- 附一页使用说明，接收方可以独立复跑。

## 五、风险与处理

- **源数据缺失**：先输出缺失清单，不擅自补值。
- **格式不一致**：以需求确认时的样例为准，变更需记录。
- **渲染差异**：交付前用 LibreOffice 实际转一遍 PDF，逐页检查版面。

---

交付不是把文件发过去，而是让对方能自己跑起来。
